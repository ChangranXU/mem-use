4. influence (@influence@) — what this entry demonstrably shaped inside its
   stated footprint window:
   - none: after inspecting the whole window, no reference or attributable
     action was established. This is not proof of zero effect;
   - referenced: mentioned or quoted, but no changed action established.
     The mention must single out this entry (its shown identifier,
     distinctive content, or list position); a remark about the results as
     a whole, such as "nothing matched", references no entry unless this
     entry was the only one shown;
   - selected: its shown identifier or preview caused retrieval of fuller
     memory content that the record shows as its own memory delivery (the
     step's result reads [memory delivery …]; span.md lists proven
     follow-ups), with no other demonstrated use of this entry's content.
     Anchor the selection action, not the result-delivery step. Selection
     proves retrieval, not benefit: positive_effect is null, and the
     returned content's effect is judged on that delivery. A retrieval whose
     result is not a recorded delivery, or opening repository code or task
     data at a distinctive path supplied by memory, is acted_on, not
     selected: nothing else judges what it returned, so its consequence is
     this entry's effect;
   - acted_on: an action uses distinctive exposed content, explicitly credits
     the memory, or demonstrably changes a prior direction because of it.
     Anchor the action or a decision later substantiated by execution. An
     unexecuted plan, a matching phrase, or routine practice alone is not use;
   - null: an action in the window uses this entry's distinctive exposed
     content, but an independent source supports that same action equally
     and the record cannot decide; or the window was not inspected
     sufficiently. Name the action and the competing source, or the unread
     evidence; positive_effect is null.

   Independent sources are the task, code and tool output, and reasoning
   stated before the delivery. The first consuming step is already
   post-exposure, so a plan first stated there or later is not one. A task
   instruction that specifies the same concrete action, or an executed or
   explicitly substantiated pre-delivery plan, explains the action: use none
   unless the memory is credited, restores a dropped plan, supplies missing
   detail, or changes direction. Earlier code can support the same action
   equally without a remedy stated in prose. If so, use null unless the
   trace distinguishes the sources. The absence of a prior plan does not
   establish memory influence. A symptom or expected output alone does
   not specify the implementation.
   When no action uses the entry's distinctive content (its specific
   mechanism, location, or remedy), use none: a shared general direction or
   generic practice is not ambiguity.
   A skipped action needs a pre-delivery announced intent or explicit credit.

   Deliveries of other items can be competing sources. Exact same-item,
   same-text copies consumed together are one source. Judge each entry by
   its own window and exposed text; changed or narrower exposures can have
   overlapping windows. When a
   preview's shown identifier selected a recorded fuller delivery of the
   same item, content both carry is the fuller delivery's to credit. The
   preview stays selected unless it shaped an action before that delivery
   arrived, or with content the fuller delivery lacks; then it is acted_on,
   citing that action, without borrowing the full read's benefit. These
   conventions allocate established influence; they do not create it.
   Credit only what this entry exposed, including shown selectors, never
   hidden keys or canonical suffixes. A preview can shape an edit without
   being opened.

   Account for every potentially shaped command in the window, including
   commands beside a memory lookup. Notes name the consuming step, actions,
   and sources; if a plausible memory-shaped action is excluded, name the
   prior evidence that explains it. For a command that mixes task-derived and
   memory-derived terms, attribute only the supported component. Anchors stay
   in the entry's window; later results can establish an anchored action's
   consequence without becoming anchors.
