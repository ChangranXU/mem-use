# 开发

## 运行测试

```bash
uv sync                                # 首次，在 checkout 内执行
npm --prefix agent install             # 首次：pi 智能体包（需要 node >= 22.19）
uv run pytest tests -q                 # 全部测试（同时运行 TS 测试）
uv run pytest tests/test_injudge.py -q # 单个文件
```

{% hint style="info" %}
测试套件不走网络。Python 测试用预制结果替换付费评审调用。TypeScript 运行器与证据工具在 `node --test` 下运行（缺 node 或尚未安装 agent 包时跳过）。夹具由 `tests/annotated_fixtures.py` 合成 schema-v10 轨迹。
{% endhint %}

## 项目结构

| 路径 | 作用 |
|---|---|
| `pyproject.toml` | uv 环境：`package = false`（工具以 `uv run -m …` 运行）、`tqdm` 运行时依赖，以及 `pytest` 开发依赖组 |
| `util.py` | 共享工具（原子写产物、安全打印） |
| `memgraph/` | 注解索引、解析、链接、HTML 渲染、判定合并、CLI（`python3 -m memgraph`） |
| `injudge/` | 步骤流、注入区间、判定契约与评审提示词（`judge.py`）、证据文件夹（`evidence.py`）、智能体运行器客户端与纠正循环（`agent.py`）、gold 边车（`gold.py`）、聚合、报告、CLI（`python3 -m injudge`） |
| `agent/` | TypeScript 评审智能体：带预算与强制作答的 pi 运行器（`runner.ts`）、只读证据工具（`evidence-tools.ts`）、事件流记录（`trajectory.ts`）、作业/结果协议（`protocol.ts`） |
| `prompts/` | 所有 LLM 提示词文件，按工具与用途分目录（经 `injudge/prompts.py` 加载） |
| `calibration/` | 受控的评审校准用例与报告打分（`python3 -m calibration`） |
| `tests/` | pytest 测试套件与共享的 schema-v10 合成轨迹构造器 |
| `doc/` | 本书（GitBook 布局：`LANGS.md` + `en/` + `zh-CN/`） |

## 评审校准

预制答案测试的是契约，而非判断质量。`calibration/` 包含受控的开发回归用例，覆盖显式
与未引用的使用、通用做法、来源与新颖性的区别、未决疑点、计划执行与逆转、有害建议、
无成效的行动、试验并放弃记忆自身的方案、保留了改动但没有能显示其收益的检查、历史范围的主张与问题摘要、已知与新建议混合、再次暴露后的纠正、读取候选条目后采用或搁置其未被记录
为投递的全文、已记录的预览/完整读取配对、对结果列表的整体评论与点名单个条目的对照、重复
搜索再次显示仍在输入中的条目，以及仅措辞不同的基线。每个用例只固定其构造能够确立的标签。投递列表的用例把其余每个条目
作为独立目标评分（`case/m2` 等）。

新增控制用例在 gold 补丁匹配且任务结果为已解决时仍保留未知效果，因为没有检查或后续使用证明该改动有益。

```bash
uv run -m calibration build calibration-cases/
uv run -m injudge calibration-cases/ -o output/calibration   # 付费；重复运行以测稳定性
uv run -m calibration score output/calibration/*/injudge-report.json
```

`score` 报告每处分歧、重复运行的逐标签稳定性，以及匹配用例的新颖性一致性。
同时按信号和 acted_on 用例的预期效果（改善、有害、无效果、未知）分别计算一致率，
避免未使用条目的 null 效果主导总分；单独报告效果稳定性、任意阶段强制作答、有跟进的区间、
实际调用数、上下文回滚和上报的输入/输出/缓存 token。实际用量包括被回滚的调用。
缺失或失败的目标单独计为不可评估，不进入一致率分母；没有有效答案时报告没有已评估标签，
不产生一致率。相同设置
衡量可重复性，改变设置衡量敏感性。除标签外还须审阅来源断言：neutral 判定仍可能错误
描述证据。`AGENTS.md` 要求付费校准取得用户授权。

所有现有用例都属于回归集。留出集必须重新编写，并在首次付费运行前冻结用例、预期标签
和评审提示词。一旦其结果被用于调优，它就成为回归数据；留出验证需要另一套新用例。

已记录后续读取的校准案例包含预览和单独绑定的完整读取，分别评分 case 与
case/read；缺失或失败的目标保留为不可评估。控制案例覆盖有用读取、未使用
读取，以及完整读取前预览已塑造行动的情形。信用归属只是确立影响后的记账
约定，不能覆盖更早行动或仅凭文字一致制造影响。

新增控制案例区分诊断代码已执行、相关输出已核实，以及预览在完整读取前引发的有用或
无用代码搜索。真实含糊案例保留供人工复核，不强制指定唯一标签。`build` 和 `score`
均接受可重复的 `--case NAME`，以显式限定实验范围；包含其后续投递，范围内缺失目标
仍标记为不可评估。改变提示词或预算属于敏感性实验；相同设置重复才测可重复性，
scorer 会提示配置或来源哈希不一致。默认输出上限改为 32768，但已有 `.env` 显式值仍优先；
实验可用 `--judge-max-tokens 32768` 覆盖。减少强制作答并不自动证明判断更准确。

## 比较记忆系统与反向审查存储条目

区分三个单位：任务的一次执行衡量基准结果，区间 × 已暴露条目衡量归因，可移植的
存储条目标识用于诊断。同一次执行内的多个投递或区间不是独立试验。每题四次应报告
每题成功比例的均值、0–4 次成功分布、全部成功和至少一次成功；后者不等于单次表现。
记忆组与无记忆组按任务 ID 匹配，并控制模型、harness、预算、任务顺序和重置策略；
缺失执行与 harness 错误单独列出。无记忆轨迹是另一次执行，不能塞入评审的
`baseline.md` 假装记忆组见过；其测试结果和成本在注入评审之外比较。持久记忆下应
保留 sequence/run 聚类，不能重采样独立注入来夸大精度；四轮对 run 级变动的估计仍有限。

已有 `aggregates.overall.memory_usage` 可通过 span ID 反查每条目的 rubric、动作锚点、
暴露文本和 episode，定位矛盾内容、有害使用、检索不匹配和有用建议。先区分版本与
暴露范围，再评价当前存储修订。忽略可能源于不相关检索、冗余或归因不明，不等于
存储条目质量差；从未投递的条目没有可评证据。保留 unknown/error/unjudged 覆盖率与
共享动作，不直接生成内在质量分、净收益或自动删除规则。优先复用已有证据关联，
无需新增付费评审器。五个信号、覆盖检查、episode 准备与动作窗口分别保护不同语义；
应先简化导航和提示词，而非删除这些保障。
