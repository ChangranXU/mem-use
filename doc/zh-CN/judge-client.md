# 评审智能体

{% hint style="info" %}
评审是构建在 [pi](https://github.com/earendil-works/pi) agent 运行时（`@earendil-works/pi-agent-core` + `@earendil-works/pi-ai`）上的智能体，由一个小型 TypeScript 运行器（`agent/runner.ts`）驱动，Python 为每条区间对话生成一个进程。Python 拥有判定契约；运行器拥有对话。
{% endhint %}

端点设置见[配置](configuration.md)（先执行一次 `cd agent && npm install`；PATH 上需要 node ≥ 22.19）。

## 对话

一个区间、一条对话。Python 物化该区间的[证据文件夹](scoring-input.md)，组装系统 prompt（与以往相同的五信号 rubric 文本），写出一个不含密钥的作业文件；运行器用且仅用三个证据工具构建 pi 智能体，以开场消息启动，让它一直运行到模型产出一条不带工具调用的最终消息。这条最终文本就是评审答案。对话的诊断信息——LLM 调用数、工具调用数、token 用量、停止原因——随结果文件回到 Python，落在操作的 `input` 记录上。

## 轨迹记录

每条对话都以 pi 事件流的形式记录为轨迹：运行器订阅智能体的事件流，把每条完成的消息即时追加到 `<output>/agent-runs/<span-id>.jsonl`。每个区间一个 JSONL，每次评判运行整体替换；每行为 `{seq, type, …}`，`seq` 在 attempt 内局部编号：

- `attempt`——开启每个运行器进程的行（纠正重试追加到同一文件；种入的 history 不触发事件，因此不会重复）。
- `message`——一条完整消息（用户开场、含工具调用与单次调用用量的 assistant 回合、工具结果），包括随后被预算回滚的回合。
- `tombstone`——`{removedSeqs, reason}`：上下文预算回滚（`context_budget_rollback`）或强制作答轮被剥离的工具尾巴（`forced_tool_tail`）从存活对话中移除了什么。
- `attempt_end`——该次尝试的诊断：答案、停止原因、forced 标记、调用计数、token 用量、错误。

强制作答消息经上下文重写进入对话（不触发事件），运行器会把它显式追加进轨迹。运行器按原文记录；Python 在每次尝试返回后把文件重写为已打码版本（唯一的打码实现留在 Python 侧），因此被保留的产物即使遇到端点回显也绝不携带凭证。操作的 `input.transcript` 以相对于输出目录的路径指向该文件。

## 预算与强制作答

两个预算约束每条对话，且都以**强制作答**收尾而非失败（采集 harness 的模式）：

- **步数预算**（`MAX_STEPS`）：LLM 调用数达到上限时，该轮被截断，追加强制作答消息（"停止调用工具；基于已收集的证据作答"），强制作答轮里任何违抗的工具调用都会被拦截。
- **上下文预算**（`CONTEXT_WINDOW`）：当估算的上下文（最近一条 assistant 消息服务端报告的 usage 加上其后消息的估算）越过水位线——上下文窗口减去预留的 `MAX_OUTPUT_TOKENS`——溢出的那一轮被回滚并注入同样的强制作答消息，使下一个请求装得下。

强制作答仍是正常的判定；操作的 `input` 记录携带 `"forced": true`，聚合计入 `forced_answers`——预算耗尽的判定是独立的评审质量状态。

## 纠正重试

Python 按判定契约解析最终答案——严格的 JSON 形状，再是区间相对语义（精确的 id 覆盖、动作锚点窗口、`none` 影响下锚点为空）。违约则触发**继续同一对话**的纠正重试：下一次运行器调用种入先前转录并追加命名违约的纠正提示，重试不付出重读成本。耗尽（尝试预算 `MAX_ATTEMPTS`）是可见的 `error` 判定并保留原始答案——绝不静默强转为中性。

没有合规层级、没有截断分类、没有输入预算闸门：输出上限截断的答案只是解析失败、走纠正重试；超大轨迹只是意味着智能体按需选读。

## 失败处理

- 运行器层失败（缺 node、未安装依赖包、作业不可读）是该区间的 `error` 判定并附 validation 注记；运行继续。不重试——相同的重试只会重付一次配置故障。
- 智能体层错误（端点认证、持续传输失败）以运行结果的 `error` 字段出现，同样成为该区间的 error 判定。
- 单次调用的传输重试、超时（`TIMEOUT`）与输出上限（`MAX_OUTPUT_TOKENS`）由运行器在每次流式调用上施加。

## 凭证

API key 只通过 `JUDGE_API_KEY` 环境变量从 Python 传给运行器——绝不经过作业文件、结果文件或任何产物——且只发往配置的端点。回显了请求的端点输出（认证/代理故障页回显凭证，无论在 HTTP 错误还是 200 应答里）会在任何文本进入判定、`judge_raw` 或 validation 注记前先打码：原始 key 及其全部百分号编码拼写、两种十六进制大小写。
