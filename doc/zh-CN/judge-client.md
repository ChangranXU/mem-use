# 评审智能体

{% hint style="info" %}
评审是构建在 [pi](https://github.com/earendil-works/pi) agent 运行时（`@earendil-works/pi-agent-core` + `@earendil-works/pi-ai`）上的智能体，由一个小型 TypeScript 运行器（`agent/runner.ts`）驱动，Python 为区间对话的每个阶段（首次调查、修复、恢复调查）各生成一个进程，各进程通过 `job.history` 延续同一条对话。Python 拥有判定契约；运行器拥有对话。
{% endhint %}

端点设置见[配置](configuration.md)（先执行一次 `npm --prefix agent install`；PATH 上需要 node ≥ 22.19）。

## 对话

一个区间、一条对话，作用域限定在其所属 episode。Python 物化该区间的[证据文件夹](scoring-input.md)，从五信号 rubric 组装系统 prompt，写出一个不含密钥的作业文件；运行器用且仅用两个证据工具构建 pi 智能体。开场消息包含确切的目标区间与紧凑文件导航；详细索引与 episode 文件仍可由工具读取。结果文件返回保留与已执行的调用计数、上报用量（含被回滚的轮次）、上下文回滚，以及对话中保留的成功步骤文件读取（`retained_evidence`）。操作的 `input` 汇总各修复阶段已执行的 LLM/工具调用、上报用量与上下文回滚，保留最后一个阶段的保留调用与 `retained_evidence` 计数，并携带最终的 `forced` 与任意阶段强制的 `any_phase_forced` 标记；停止原因留在轨迹中。

## 轨迹记录

每条对话都以 pi 事件流的形式记录为轨迹：运行器订阅智能体的事件流，把每条完成的消息即时追加到 `<output>/<run-stamp>/agent-runs/<span-dir>.jsonl`。每个区间一个 JSONL，每次评判运行整体替换；每行为 `{seq, type, …}`，`seq` 在 attempt 内局部编号：

- `attempt`——开启每个运行器进程的行，并记录 `phase: "judge"` 或 `"repair"`。各阶段追加到同一文件；种入的 history 不触发事件，因此不会重复。
- `message`——一条完整消息（用户开场、含工具调用与单次调用用量的 assistant 回合、工具结果），包括随后被预算回滚的回合。
- `tombstone`——`{removedSeqs, reason}`：上下文预算回滚（`context_budget_rollback`）或强制作答轮被剥离的工具尾巴（`forced_tool_tail`）从存活对话中移除了什么。
- `attempt_end`——答案、停止原因、forced 标记、错误、保留对话的计数/用量，以及本阶段已执行的调用/用量与回滚。只有后者会在各阶段间汇总。

强制作答消息经上下文重写进入对话（不触发事件），运行器会把它显式追加进轨迹。运行器按原文记录；Python 在每次尝试返回后把文件重写为已打码版本（唯一的打码实现留在 Python 侧），因此被保留的产物即使遇到端点回显也绝不携带凭证。操作的 `input.transcript` 以相对于运行文件夹的路径指向该文件——`agent-runs/<span-dir>.jsonl`。

强制答案若同时包含被阻止的工具调用，运行器在为工具尾部写入 tombstone 后重新记录保留的 assistant 文本，确保回放仍包含最终答案。

## 预算与强制作答

两个预算约束每条对话，且都以**强制作答**收尾而非失败：

- **步数预算**（`MAX_STEPS`）：LLM 调用数达到上限时，对话被截为最后一个作答轮：强制作答消息告知智能体预算已耗尽，要求它停止调用工具，并基于已收集的证据立即写出最终答案；强制作答轮里任何违抗的工具调用都会被拦截。
- **上下文预算**（`CONTEXT_WINDOW`）：使用最近一条适用的 assistant usage 加上后续消息估算；没有可用输入用量时（含只有输出用量的响应），根据消息、系统提示词和工具 schema 估算。水位线预留 `MAX_OUTPUT_TOKENS` 和强制作答消息的估算大小；越过水位线时回滚溢出轮次并注入强制作答消息。

缺失证据后的恢复调查**最多使用四次模型调用，包含最终作答**；若 `MAX_STEPS` 更低则服从该值。四次上限允许最多三轮取证和一轮强制作答，不会重新获得完整的首次调查预算。既有上下文水位线仍可能更早触发强制作答。这是固定策略，不增加配置项。

在修复或恢复调查之前，运行器把输出上限设为 `MAX_OUTPUT_TOKENS` 与先前答案留下的上下文余量中的较小者，同时保持证据历史完整。越界或为空的步骤文件读取不计入保留证据。

在调查成果仍被保留的情况下，强制作答可以是有效判定。若对话中仍然没有一次成功的步骤文件读取，即使 JSON 语法完全合法也会进入修复，而不是成为普通的 neutral 判定；只读导航文件不够。只有在最终答案是强制作答时，操作的 `input` 才携带 `"forced": true`，而 `any_phase_forced` 会跨修复保留更早的强制阶段。

## 纠正重试

Python 检查严格 JSON 形状和区间相对语义（精确 id 覆盖、动作锚点窗口、`none` 下锚点为空）。答案合法时不增加任何模型调用。

答案不合法时，使用完整对话和校验错误进行**一次禁用证据工具的修复调用**。修复只处理违约部分，保留有证据支持的评估。Python 再次校验结果；修复仍不合法则成为可见的 `error`，不继续盲目改写。

只有修复阶段明确返回控制消息 `{"needs_evidence": "specific missing fact and step/file"}` 才重新开放调查；它不是判定。后续运行器恢复完整 `job.history`、启用证据工具，并用 `agent.prompt(...)` 添加针对性追问。这是 pi 以新指令原生续接的方式：它保留已有消息。

`MAX_ATTEMPTS` 限制全部运行器阶段（首次调查、修复与恢复调查）的总数。耗尽时保留可见错误和已打码的答案文本。不放宽解析器、不剥离格式包装作回退，也不对已合法答案追加模型调用。

输出上限截断的答案无法通过契约解析，会走纠正重试。超大轨迹意味着智能体按需选读证据文件夹。

## 失败处理

- 运行器层失败（子进程无法启动、非零退出、超过运行时限、或写不出可读结果）是该区间的 `error` 判定并附 validation 注记；运行继续。不重试——相同的重试只会重付一次故障。缺 node、缺运行器、或 agent 依赖树未安装属于配置误用，在任何付费调用之前即以明确错误快速失败。
- 智能体层错误（端点认证、持续传输失败）以运行结果的 `error` 字段出现，同样成为该区间的 error 判定。
- 单次调用的超时（`TIMEOUT`）与输出上限（`MAX_OUTPUT_TOKENS`）由运行器在每次流式调用上施加；不做传输重试——请求失败即以运行结果的 `error` 字段出现。

## 凭证

API key 只通过 `JUDGE_API_KEY` 环境变量从 Python 传给运行器——绝不经过作业文件、结果文件或任何产物——且只发往配置的端点。回显了请求的端点输出（认证/代理故障页回显凭证，无论在 HTTP 错误还是 200 应答里）会在任何文本进入判定、`judge_raw` 或 validation 注记前先打码：原始 key 及其全部百分号编码拼写、两种十六进制大小写。

打码也会处理 JSON 字符串转义，包括轨迹记录内嵌的答案 JSON，避免转义后的凭证留在保存的输出中。
过深的字符串包装整体打码。UTF-8 写入中断仍会执行打码；若无法保存打码后的轨迹，则删除原始文件，并将区间记录为带有 input 诊断的错误。
